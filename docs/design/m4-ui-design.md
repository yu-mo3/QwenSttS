## 二、已锁定的设计决策

| # | 项 | 决定 | 理由 |
|---|---|---|---|
| 1 | 光球渲染 | **QWidget + QPainter 纯代码自绘** | 项目零美术素材；自绘可让状态连续插值（不会跳变），且不引入 QML 文件与 QtQuick 运行时分发 |
| 2 | 依赖 | **PySide6-Essentials**，不是完整 PySide6 | 完整包会拖进 WebEngine（实测 131.7MB）+ Addons（40.5MB），我们一行都用不到。Essentials 只 82.2MB，提供同一个 `PySide6` 命名空间 |
| 3 | 线程模型 | **命令进队列 / 事件出回调** | 见 §四。UI 绝不在非 GUI 线程碰控件 |
| 4 | 事件契约 | 抽 `app/orchestrator/events.py`，两个编排器共用 | 修 KI-006。UI 若依赖 `payload['total']` 而 assistant 不发，就是必现的 KeyError |
| 5 | 会话可重入 | `run()` 前置归位 + `Speaker.stop()` 闭锁 | 修 KI-007。托盘「重新开始会话」会直接踩到 |
| 6 | 设置持久化 | 界面上显式点「保存到 .env」，不静默写盘 | `.env` 是配置的唯一事实来源，但**静默改写用户的密钥文件不可接受** |
| 7 | 关窗 | 确认框三选一：退出 / 最小化到托盘 / 取消 | 用户要求「弹确认框」且要托盘，两者必须能共存 |
| 8 | 麦克风电平 | L5 暴露一个**限频**的 `on_level` 钩子 | UI 不能自己开第二个麦克风流（会抢设备）。见 §五 |

`ChatProvider` / `SpeechRecognizer` / `sounddevice` 出现在 L6。

## 四、线程模型（本期最容易写错的地方）

```
         GUI 线程                         后台线程（ayuan-session）
   ┌──────────────────┐               ┌──────────────────────────┐
   │ MainWindow       │               │ VoiceAssistant.run()     │
   │  ├ 光球 / 历史    │               │  ├ 主帧循环（状态机）      │
   │  └ Controller    │               │  ├ ayuan-input 读麦克风    │
   └───────┬──────────┘               │  └ ayuan-speak 播报        │
           │                          └───────────┬──────────────┘
           │  ① 命令：queue.Queue（线程安全）        │
           ├─────────────── post(cmd) ────────────>│  每帧 drain 一次
           │                                        │
           │  ② 事件：EventBridge.emit → Qt 信号     │
           │<──────── queued connection ────────────┤  任意线程调用
           │                                        │
      槽函数在 GUI 线程执行，直接刷控件
```

三条纪律：

1. **UI → L5 只走命令队列**。`listen_now` / `stop_speaking` / `submit_text` /
   `reset` / `shutdown` 五种命令，主循环每帧 `get_nowait` 排空。
   好处：不需要任何锁，不需要 UI 知道 L5 内部的字段。
2. **L5 → UI 只走事件回调**，由 `EventBridge` 转成 Qt 信号。
   `EventBridge` 在 GUI 线程构造，因此从 `ayuan-input` / `ayuan-speak`
   发出的信号是 **queued connection**，槽函数自动回到 GUI 线程。
3. **播报线程绝不 join 主线程**（M3 审查 X1 的教训），UI 也不许在槽里
   阻塞等待 —— 否则「说停就停」会第二次变成死代码。

## 五、电平（波形）为什么不从事件总线走

技术面板要显示实时波形。麦克风每 20ms 一帧 = 50 次/秒，若每帧都发事件，
事件总线会被刷屏，真正的状态事件被淹没。

方案：`VoiceAssistant` 增加一个**可选的、限频的**电平钩子

```python
VoiceAssistant(config, on_event=..., on_level=lambda level, source: ...)
#   source: "mic"     —— 输入帧的 RMS（约 20 次/秒）
#           "speaker" —— 播放块的 RMS（约 20 次/秒）
```

- 它是**可选参数**，不传就零开销（连帧能量都不算）
- 限频在 L5 内做（每 3 帧算一次），UI 不需要自己节流
- 为什么不让 UI 自己开麦克风：同一次会话里两个 `InputStream` 抢同一个设备，
  Windows 上会互相干扰。**设备只能有一个持有者**，这一条和「业务代码不直接碰硬件」是同一个道理

### 光球的四态（`orb.py`）

| 状态 | 配色 | 动效 |
|---|---|---|
| 待机 IDLE | 冷青 `#3AA6B9` | 缓慢呼吸（`sin` 周期 ~4s），外层光环最暗 |
| 聆听 LISTENING | 亮绿 `#4ADE80` | 外扩涟漪，**半径跟随麦克风电平**（用户在说话，球在回应他） |
| 思考 THINKING | 琥珀 `#FBBF24` | 一段弧沿圆周旋转（`QConicalGradient`） |
| 说话 SPEAKING | 品红 `#C084FC` | 脉动，**振幅跟随播放电平** |

实现要点：`QTimer` 30fps 重绘；状态切换用**颜色与半径的线性插值过渡**
（`0.25s`），避免生硬跳变；`paintEvent` 里全部用 `QPainterPath` +
径向渐变，不用任何图片。

**验收标准**：`orb.py` 里的「状态 → 目标配色/半径」映射写成**纯函数**
（`orb_targets(state, level, t) -> OrbFrame`），这样它能被无 GUI 的
单元测试锁住 —— Qt 控件本身不测，纯逻辑必须测。

### 对话历史（`history.py`）

- 气泡列表，用户右/阿源左；每条带**时间戳与耗时**（识别/对话/首字）
- 从事件流增量追加，不重绘整个列表
- 「没听清」「出错」「被打断」也要显示成条目 —— **静默失败是 M2/M3 反复踩的坑**，
  界面上必须看得见

### 技术面板（`tech_panel.py`）

四个分组，可折叠：

1. **电平波形** —— 最近 ~3 秒的滚动曲线（mic / speaker 双色）
2. **设备** —— 当前输入/输出设备名与索引、是否免提模式、推荐路由
3. **参数** —— 模型名、采样率、帧长、唤醒阈值、静默超时
4. **事件日志** —— 原始事件流（名 + 载荷摘要），排障时最有用的那一栏

### 设置面板（`settings_panel.py`）

| 项 | 生效方式 |
|---|---|
| 输入/输出设备关键字 | 需**重启会话**（要重开音频流），按钮上会写明 |
| 唤醒阈值 / 停阈值 | 立即生效（重建检测器） |
| 静默超时 | 立即生效（纯数值） |
| TTS 音色 | 立即生效（下一句起） |
| 「保存到 .env」 | 显式点击才写盘；行级改写，**保留其它行与注释原样** |

## 七、验证方案

### 自动化（新增测试，全部不需要显示器）

沿用项目既有的「纯函数测试」风格，用 `QT_QPA_PLATFORM=offscreen` 只在
必要时碰 Qt：

| 测试 | 锁住什么 |
|---|---|
| `test_events_pure.py` | 每个事件的载荷键集合被固化；`tts_done` 两个编排器都带 `total`（KI-006 的 KeyError） |
| `test_assistant_pure.py` 扩 | `run()` 连续两次不抛 `InvalidTransition`（KI-007①） |
| `test_audio_pure.py` 扩 | `Speaker.stop()` 在句间窗口闭锁，下一句不再出声（KI-007②） |
| `test_ui_pure.py` | 光球状态→配色/半径映射；`.env` 行级改写不碰其它行；历史条目的格式化 |
| `test_assistant_pure.py` 扩 | 文本注入走完一整轮；命令队列 `stop_speaking` 生效 |

### 人工验收（必须真人做）

1. 界面能起、能关、关窗有确认
2. 喊「阿源」→ 光球从待机切到聆听、涟漪跟随自己的音量
3. 说话 → 思考 → 说话，四态切换不错乱
4. 打字发送 → 得到回复与语音
5. 点击「停」→ 播报立即停止
6. 托盘：隐藏 / 显示 / 重新开始会话 / 退出
7. 设置面板改阈值 → 保存 → 重启后仍生效

> ⚠️ **唤醒词无法自动验证**（KWS 只认真人语音，见 status.md §六.1），
> 第 2 条必须真人复测。

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| Qt 控件必须活在 GUI 线程，跨线程刷控件会崩 | §四 的桥接纪律；代码评审重点看这一条 |
| 30fps 重绘 + 50Hz 电平会不会吃满 CPU | 电平限频到 ~20Hz；`paintEvent` 内不分配大对象；实测后再调 |
| 抽统一事件会动到 M2 已在用的 `pipeline.py` | `TurnResult` 从 `pipeline` 与 `assistant` **再导出**，现有 import 与测试不破 |
| 界面线程杀不干净，退出后麦克风仍被占用 | `closeEvent` 必须 `shutdown` 命令 + `join(timeout)`；加一条「退出后设备已释放」的验收 |
| 设置面板写坏 `.env` | 行级改写 + 只碰自有键；单元测试覆盖「其它行与注释保持不变」 |
